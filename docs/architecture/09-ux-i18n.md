# 09 — UX amigable e idioma (ES/EN)

## Hallazgos previos

La SPA ya estaba **mayormente en español**, pero:

- Mezclaba jerga técnica en inglés (`On hand`, `JWT`, `PKCE`, `RBAC`, códigos `usr_dev_*`, estados `IN_REVIEW`).
- El login hablaba más al desarrollador que al usuario de negocio.
- No había forma de cambiar a inglés.

## Decisión de producto

| Aspecto | Decisión |
|---|---|
| Idioma por defecto | **Español** (`es`), con detección de `navigator.language` |
| Segundo idioma | **English** (`en`) con selector persistente (`localStorage`) |
| Tono | Claro, de negocio; sin acrónimos de seguridad en pantallas de usuario |
| Códigos internos | Se traducen a etiquetas (`br_norte` → Sucursal Norte / North branch) |
| Errores API | Se mapean a mensajes humanos (p. ej. SoD → “No puedes aprobar una corrida que tú mismo preparaste…”) |

## Dónde vive

- Catálogo: `apps/web/src/i18n/messages.ts`
- Store + helpers: `apps/web/src/i18n/locale.ts`
- Selector: `apps/web/src/components/LanguageSwitcher.tsx`

## Qué sigue (opcional)

- i18n de notificaciones del consumer (`apps/notification`)
- Preferencia de idioma por usuario en BD
- Formatos regionales adicionales (fecha/periodo de nómina)
